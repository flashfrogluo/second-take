# 标注范例

## 一、语言习惯

- 判断用陈述句，不写「我认为」「可能」「似乎」「值得注意」。
- 引用 CoT 原文一律加双引号，不转述、不概括。
- 每条固定四段：错误性质 → 引用原文 → 对照依据 → 定性。
- 关键错位要写出它的结构层面影响，不只报「漏了」。

## 二、符号约定

- **【标红】**：该处引用了「已知信息/前文」来支撑，但支撑不成立。
- **【重点】**：错误本体。
- Markdown 里分别用引用块和粗体呈现。

## 三、完整示例

> 以下为虚构的合成示例，仅演示格式与判断方式。示例所在的领域特征不构成任何可迁移规则，请勿套用到其他任务；迁移规则一律以 `SKILL.md` 与 `references/` 中抽象后的表述为准。

**输入**

- UP（用户指令）：白天、安静的厨房，女主人在木质台面上切胡萝卜，固定机位、中景、自然光，不要出现台词。
- Caption（素材描述）：0-5s 女人站在窗边台面前切胡萝卜，阳光从左侧窗进入。
- 目标产物：一段 5 秒视频，窗在画面右侧，光从右前方来，人物位于画面中央偏左。
- CoT（深度思考）：略。

**输出**

> 本次依据：目标＝一段 5 秒视频（窗在画面右侧、光从右前方来、人物位于画面中央偏左）｜参考＝无｜待改产物＝CoT（略）；其中目标为提供。

**产物冲突（描述亦不符）**

1. 视觉冲突：CoT 说「阳光从右侧窗斜切进来，在台面上拉出一道长影」，但目标产物中窗位于画面右侧、人物位于中央偏左，光是从右前方平铺进来的，台面上没有长投影；Caption 中无对应内容；
2. 视觉冲突：CoT 说「固定机位让空间显得逼仄，暗示她的压抑」，但目标产物中景构图留白充足，画面读不出逼仄感，Caption 中无对应内容；

**产物/参考冲突（描述相符）**

无

**参考冲突（描述亦不符）**

无

**指令冲突**

1. 冲突：CoT 说「加一句画外音点明她的心事」，但 UP 明确要求「不要出现台词」，【重点】该判断直接推翻了显式约束；

**覆盖不全**

UP 中把「木质台面」「自然光」「固定机位中景」列为硬指标，CoT 只在开头一笔带过，未分析自然光方向对切菜动作可读性的影响，也未说明固定中景如何保证手部动作始终在画面内。未分析的部分：光线方向与材质反射的关系、中景构图对手部动作的包容度；

**推理缺陷**

1. 无据引用：CoT 说「台面上那把**【标红】**祖传的刀」，把「祖传」当作事实使用，但它在 UP 中未提及，Caption 中无对应内容，CoT 前文也无推理和论证；
2. 强行推理：CoT 说「台面是**【重点】**深色胡桃木」，但 UP 中只说了「木质台面」，前文也未论证。「深色胡桃木」在此后关于光线反射的推演中作为关键条件，并由此强行推出台面会出现镜面高光；
3. 常识性错误：CoT 说「切胡萝卜的节奏会带出清脆的咀嚼声」，混淆了切菜声与咀嚼声，违反生活常识；
4. 前后矛盾：CoT 前文说「全程无台词，靠画面叙事」，后文又说「用一句独白收尾」，同一段推理内部自相冲突；

**改写指令汇总**

- 「阳光从右侧窗斜切进来，在台面上拉出一道长影」→ 应改为：「自然光从右前方平铺进入，台面无明显投影。」
- 「固定机位让空间显得逼仄，暗示她的压抑」→ 应改为：「固定中景构图稳定，留白充足，情绪表达交给动作节奏。」
- 「加一句画外音点明她的心事」→ 应改为：「删除全部台词与画外音，仅保留环境音。」
- 「台面上那把祖传的刀」→ 应改为：「台面上放一把厨刀。」（UP 未指定来源，不得自行补全）
- 「台面是深色胡桃木」→ 应改为：「台面为木质，纹理与颜色未指定，不得据此推导反射效果。」
- 「切胡萝卜的节奏会带出清脆的咀嚼声」→ 应改为：「切胡萝卜产生短促的切割声。」
- 「用一句独白收尾」→ 应改为：删除，与「全程无台词」保持一致。

## 四、优化指令（最后一段，可直接复制走）

改写指令与修改要点都是**给模型看的输入**，不是交付物。最后必须再给一段自包含的优化指令，让模型直接产出内容。

固定四段：原始 UP → 原始 CoT → 必须落实的修改 → 输出要求。

**先判定产出目标**——这是最容易错的一步。用户要的是「更好的内容」：

- UP 是提问或要一份内容 → 产出**最终回答**（还要按 UP 的格式要求，如「一长条、不分点」）；
- UP 的交付物本身就是推理过程（提示词工程里 CoT 即产物）→ 产出**改写后的 CoT**；
- 判不了就问一句。

判错目标的症状很固定：用户拿回去的还是一段「嗯，用户问的是……」的思考过程，而不是他要的答案。产出目标不是 CoT 时，必须在输出要求里显式写「不要输出深度思考」。

**原始 UP 必须全文内嵌**，不写「见上文」——用户会把这一段单独复制走，目标模型看不到任何上下文。
**输出要求显式禁止**回传分析、说明、对比表或建议，否则模型会再给一份优化指令。

### 最关键的一条：模板 A 绝不能内嵌 CoT 全文

CoT 是病原。把它整段贴进生成指令，模型会照着它的语气重写一遍，输出变成「嗯，用户问的是……首先我需要分解这个问题」——**用户要的是答案，不是这段东西**。写「忽略它」也拦不住，内容就在眼前。

正确做法：把 CoT 里值得留下的判断**萃取成 5-10 条有效结论清单**，用陈述句写，和「必须落实的修改」一起给。要的是结论，不是推理过程。

只有模板 B 才内嵌 CoT 全文——那种情况下 CoT 本身就是交付物，本来就要被改写。

### 粘贴位置

**粘贴位置由用户决定，不要强制开新对话**——原始对话上下文对用户有价值，两种用法都要支持。粘回原始对话时，指令开头加一段**定向忽略声明**：

**首轮用「全量重写」版**：

```
下面是本次任务的完整输入。
本对话中用户此前提出的全部指令、追加要求、表达习惯与思维方式继续有效，请照常遵循，并沿用用户的语言风格与偏好。
只忽略本对话中上一轮那段深度思考，以及由它直接产出的那一版回答——这部分经质检判定不合格，
不得沿用其结构、措辞、篇幅与结论。
```

**第二轮以后默认用「定点修复」版**——上一版主体已成立时，重写会让模型把合格段落一起丢掉（踩过：重写出一版带样例的新稿，反而把上一版已有的应急条目删没了）。忽略范围收窄到**只忽略那段 CoT 里的错误取舍**，那一版回答声明为"除点名处外成立"：

```
下面是本次任务的完整输入。
本对话中用户此前提出的全部指令、追加要求、表达习惯与思维方式继续有效，请照常遵循，并沿用用户的语言风格与偏好。
只忽略本对话中上一轮那段深度思考——其中关于「<取舍 1>」「<取舍 2>」的判断均不成立，不得沿用。
上一轮那一版回答，除下面【必须落实的修改】点名的地方外，其余内容成立，按原样沿用；未点名处不要重写，
不要更换章节划分与标题，不要删改已合格的段落。（若上下文中找不到那一版，按下面的素材与结构完整写一遍即可。）
```

括号里那句兜底不能省——用户可能把指令粘到别处，上下文里没有那一版，缺了它会直接卡住。

指令里既然没有 CoT 正文，就别写「下面【原始 CoT】」——指不到。直接说「本对话中上一轮那段深度思考」。

**要切掉的只有那一段不合格的推理，不是整个对话。** 用户的长上下文里有他反复强调的要求、表达习惯、思维方式，那是模型必须学习和沿用的东西，一刀切地「忽略本对话中所有回答」等于把最有价值的部分也丢了。

模板 A（产出目标 = 最终回答，UP 是提问时用它）：

```
下面是本次任务的完整输入。
本对话中用户此前提出的全部指令、追加要求、表达习惯与思维方式继续有效，请照常遵循，并沿用用户的语言风格与偏好。
只忽略本对话中上一轮那段深度思考——<点名它错在哪几个取舍上>，这些判断均不成立，不得沿用。
<定点修复时加这句>上一轮那一版回答，除下面【必须落实的修改】点名的地方外，其余内容成立，按原样沿用；未点名处不要重写，不要更换章节划分与标题。（若上下文中找不到那一版，按下面的素材与结构完整写一遍即可。）

【原始 UP】
<UP 全文，含后续追加指令>

【有效结论清单】
下面这些结论经核对成立，可以直接采用。不要逐条罗列，按后面的章节打散归入，也不要标注出处：
1. <结论 1>
……

【必须落实的修改】
1. <修改要点 1：改成什么，不要只写"要注意什么">
……

【输出结构】
按下面的章节组织，节序不变；标题可自拟，但必须是名词短语，不得用祈使句、口号或口语：
1. <名词短语标题>【附样例：<样例名>】
2. <名词短语标题>【附样例：<样例名>】
……
末段：收尾询问段，独立成段，不加小标题，不得省略。

【输出要求】
- 只输出面向 UP 的最终回答正文，不要输出任何分析过程、修改说明、前后对比、建议清单或开场白。
- 不要输出任何形式的思考过程或推理过程。
- 禁止思考腔：不得出现「嗯」「用户问的是」「我需要」「首先」「接下来考虑」「让我」「因此回答必须」「总结起来」这类措辞。
- 每个章节用「## 」小标题开头，不用「一、二、三」这类编号。
- 每节第一句话是该节的结论或判断，后面才是展开；不要先铺陈后总结。
- 关键动作、标准、时间点用**加粗**标出，但不要通篇加粗，也不要为凑数加粗。
- 凡提到清单、表格、模板、流程的地方，都要落成**能直接照抄的样例**，不要只描述它应该有什么字段。样例用 Markdown 表格或带勾选项的清单，不混在段落里；体量 4-6 行 / 3-4 列，<某张表>不受此限制；行数与列数的限制不得导致删减条目或合并字段。
- 样例里的人名、机构名、具体数值一律用占位符（「××」「某××」「20XX」「X 小时内」），不得编造真实名称与精确数值。每个样例下面用一句话说明它什么时候填、谁来填。
- 检验确有依据才给具体数值；没有依据就写定性标准，不许编造精确数字或岗位名来凑。
- 同一句判断不得出现两次：既不得跨节重复，也不得在一节正文与它自己的样例里重复。
- 不得出现三个以上「加粗名词 + 同一句式」的并列串。
- 句子成分写全：中文里读起来必须有的字不得省略——「也知道」不写「也知」、「可以使」不写「可使」、
  判断句写全「是……，而不是……」，助词「的 / 了 / 过」、判断词「是」、介词「在 / 使」该有的都要有。
  不得为压字数省句子成分；凡是需要读者自己补字才读得通的句子，一律重写。
- 第一人称要有节制：<个人总结 / 收获 / 复盘类保留第一人称，但「我」字句不超过 2-3 句，
  集中在开头与结尾，中间论述用客观陈述；说明 / 分析 / 报告类直接不用第一人称>。
  不要出现连续两句以上以「我」开头的主观句。
- **本指令中出现的一切要求、规则、结构说明都不得出现在正文中**，正文只面向 UP 的读者。

  「按上面的章节」「有效结论清单」「附样例」这类措辞。
- 不得新增 UP 中不存在的需求与信息。

- 总篇幅 <X>-<Y> 字（含样例），面向专业读者；不得为凑字数注水。

【判定标准：先自己写一份，再按它写】
动笔之前，先针对本次任务自己写一份验收标准，写完再动笔。这份标准只用于你自己判定，不得输出，也不得写成正文的一节。
写标准的规范：
1. 8-12 条，每条一个 Yes/No 问句，答「是」= 合格。约束类写成否定式（「是否未出现……」）。
2. 一条只判一件事。含「和」「并」「且」的拆成两条。
3. 不许写裸形容词。想写「合理」「完整」「通顺」时，必须落成能判的落点：什么现象出现即算不合格。
4. 每条后面跟一句「凭什么判」——依据 UP 的哪句话、哪条常识。写不出依据的条目删掉。
5. 按本次任务自身的结构分组（按章节、按模块）。
6. 覆盖两类：UP 明写的要求；UP 没写但行内默认必须满足的隐性约束。

1. <种子条目 1>
2. <种子条目 2>

自检在输出之前完成；自检过程、自答记录、以及「经检查……」这类表述一律不得出现在正文中，也不得写成正文的一节。

1. <自检条目 1>
2. <自检条目 2>

10. 【输出要求】里点名的思考腔、元要求措辞与编造内容，是否一次都没出现？
```

**【输出结构】是模板 A 里最容易漏、也最不能漏的一段。** 只写「可分节」「按清晰易读的方式组织」，模型会输出一坨没有层级、没有重点的平铺文字——用户的反馈固定是「没有格式没有重点」。骨架要给到能照抄的程度：分几节、每节主题、每节覆盖哪几个点、每节多少字。

但骨架写错语气，比不写骨架更糟。四条：

- **标题用名词短语。** 骨架里的标题就是模型会抄的标题。写「先把时间轴钉死」「底线与复盘」「必须做到…」，整篇标题都会带着祈使腔和口号腔，读者一眼看出是模板。
- **结构统一，不自相矛盾。** 不要同时写「严格按下面结构，不要自创」和「标题可自拟」——模型任选一条，输出不可控。统一成一句：按这个划分写，标题可自拟，但必须是名词短语。
- **规定效果，不规定句式。** 要求「结论前置」「关键处给出可检验的落点」是对的。写成「每条策略写成怎么做 + 判断标准」，模型就当填空题做，全篇变成「产出物为…判断标准是…」的八股——机械感比原来那版还重。
- **不许写元叙述。** 「注明供用户纠正」「说明这是工作定义」会被原样搬进正文，读者完全不知道这句话在跟谁说话。

「原样保留」只用于模板 B。模板 A 里必须改成「按骨架重新归类」——否则「保留原文顺序」和「重新组织结构」两条指令互相打架，模型会选保守的那条，也就是平铺。

### 末尾三段的分工

模板 A 的末尾三段各有职责，顺序不能换：

| 段 | 谁写 | 作用 |
|---|---|---|
| **【判定标准】** | 目标 AI 自己（按我们给的规范） | 事前定义"这个领域什么叫好"，覆盖我们没见过的错 |
| **【已知缺陷】** | 我们（种子 3-6 条） | 锚住上一版实际犯过的错，它不知道自己删了哪条 |
| **【成稿自检】** | 我们（成品 10-12 条） | 写完统一过一遍，答「否」当场改 |

**【成稿自检】里不要重列【输出要求】已经点名的东西**（禁用词表、篇幅、占位符），用指代词带过——「【输出要求】里点名的思考腔与元要求措辞，是否一次都没出现」。重列一遍会让指令臃肿，也会让模型把同一件事展开两次。

判定标准段是**默认加**的。只有目标模型明显能力弱、UP 极简、缺陷已完全可枚举、用户要最短指令这四种情况才去掉。写法与护栏见 `references/自生成rubric元指令.md`，条目写法见 `references/成稿自检清单.md`。
