# 迭代工作流 · 如何持续改进 second-take

面向维护者：当你要改硬约束、加 reference、补语料、做回归时，按这里走，避免再踩已经踩过的坑。

## 0. 两条铁律（来自语料纪律）

1. **案例只用于提炼经验，不进知识库。** 用户给的具体对话、打分项、画面，一律是测试案例，不是知识。`SKILL.md` / `references` / `README` 里不得出现案例的专有名词、具体条目名、真实数值、领域独有做法。
2. **沉淀顺序固定：症状 → 根因 → 机理 → 规则。** 只记症状的规则治不了病。抽象判据：把规则里的专有名词全换成占位符再读一遍，仍成立的是机理（可入库），不成立的是做法（留案例文件）。一句话：删掉名词还剩什么，什么才是能迁移的。

## 1. 改一条硬约束的标准动作

1. 在 `SKILL.md` 正文「硬约束」段落加/改条目，编号顺延；脚本或正文里记的条数（当前 28）同步更新。
2. 若这条约束需要展开解释，写到 `references/硬约束详解.md` 对应条目，**不要**把长篇解释直接堆在 SKILL.md（保持 SKILL.md 可扫描）。
3. 到 `README.md` 的目录树登记新文件/新条目，保持三处（SKILL.md 正文、硬约束详解、README 目录）条数一致。
4. 跑回归：从 `corpus/sanitized/` 取 2-3 个相关案例，用本 skill 实际诊断一遍，确认改动没让已有合格项消失（踩过：第二轮重写把上一版某条整条删没了）。
5. 改完在 `CHANGELOG.md` 记一笔（PATCH / MINOR）。
6. 同步到已安装目录：`cp -Rf <工作区>/second-take/. ~/.workbuddy/skills/second-take/`。
7. 决定发布时升版本号（`SKILL.md` frontmatter `metadata.version`），推 GitHub。

## 2. 加一个 reference

- 触发：某条硬约束解释超过 ~15 行，或某类场景（如「生成类提示词」「caption 写作」）需要独立方法论。
- 命名：`references/<主题>.md`，与现有文件名风格一致（中文主题）。
- 纪律：脱敏、不写死本机路径（用 `/path/to/...` 或相对路径）、不放真实业务数据。

## 3. 补语料 / 做回归（私有，不进仓库）

- 语料放在 skill 目录**之外**的 `corpus/`（与 `second-take/` 同级），永远不 `git add`。
- 流程：原始素材丢 `corpus/inbox/` → 脱敏后入 `corpus/sanitized/`（用 `_template.md`）→ 用 skill 跑诊断，输出存 `corpus/runs/YYYYMMDD-<caseid>.md` → 对照 `期望诊断要点` 看是否命中。
- 一个案例若反复暴露同一类问题，才值得提炼成「机理」回灌到 references；否则只留在 corpus。

## 4. 跨 agent 适配

- `SKILL.md` frontmatter 只认 6 字段：`name / description / license / compatibility / metadata / allowed-tools`（agentskills.io 规范）。
- 各 agent 目录（`.claude/skills`、`.agents/skills`、`.gemini/skills` 等）放同一份即可；解释性内容外移到 references，保持 SKILL.md 精简。

- [ ] `SKILL.md` / `references/`（11 个） / `README.md` + `README_EN.md` / `LICENSE` / `.gitignore` / `CHANGELOG.md` / `docs/`（迭代工作流.md · 四标准质检法.md · guide-en.md · ROADMAP.md · index.html · assets/） / `.github/`（CONTRIBUTING.md · SECURITY.md · workflows/） / `prompts/` / `tests/` / `install.sh` / `update.sh` 齐全
- [ ] `CHANGELOG.md` 记到当前版本
- [ ] `diff -rq <工作区>/second-take ~/.workbuddy/skills/second-take` 无差异
- [ ] 无真实密钥 / 本机路径 / 客户数据
- [ ] 建仓库 `flashfrogluo/second-take`，只传 `second-take/` 内容（勿拖整个工作区）
